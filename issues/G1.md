# G1 — A missing logger is silent by construction: the constructor of every …

## Finding / 问题

- EN: A missing logger is silent by construction: the constructor of every SQL class defaults the parameter to a live `NullLogger` instance — `private readonly LoggerInterface $logger = new NullLogger()` in `SqlBuilder` and `SqlDelete` — and `HasWhereClause::getLogger()` only guarantees the same interface. A call site that forgets the logger therefore gets a builder that reports nothing. The logger must be passed in through the constructor and required, so the omission fails at assembly time rather than being silent at runtime.
- 中文: 缺 logger 在构造上就是静默的：每个 SQL 类的构造函数都把参数默认成一个活的 `NullLogger` 实例——`SqlBuilder` 与 `SqlDelete` 里写的是 `private readonly LoggerInterface $logger = new NullLogger()`——而 `HasWhereClause::getLogger()` 只保证同一个接口。因此忘记传 logger 的调用点得到的是一个什么都不上报的 builder。logger 应当由构造函数明确传入且为必填，让这个遗漏在装配时就失败，而不是在运行时保持沉默。
- Where / 位置: `src/SqlBuilder.php:23 · src/SqlDelete.php:26 · src/HasWhereClause.php:45`
- Verification / 验证: static / 仅静态
