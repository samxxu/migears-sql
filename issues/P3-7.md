# P3-7 — count() documents itself as returning "the total number of matching …

## Finding / 问题

- EN: count() documents itself as returning "the total number of matching records" and declares that it ignores limit, offset and orderBy — but not groupBy. With a groupBy() applied it returns the number of groups instead, so a caller paging by total gets a number that silently describes something else.
- 中文: count() 的文档称自己返回「匹配记录总数」，并声明忽略 limit、offset 与 orderBy——但没有提 groupBy。加了 groupBy() 之后它返回的是分组数，于是按总数分页的调用方拿到一个静默描述着别的东西的数字。
- Where / 位置: `src/SqlSelect.php:179-192`
- Verification / 验证: reproduced / 已实证

  ignored. `src/SqlSelect.php:176-182` now reads "Counts the matching records (ignores limit/offset/orderBy)"
  and states that `groupBy()` makes it count the groups, one row per group, in the wrapped subquery. Level
  kept at P3: the rubric's P2 is for an unintended silent wrong result, and this path is intended and tested
  — had the count-of-groups been unintentional, the finding would have been the behaviour, not the sentence.
