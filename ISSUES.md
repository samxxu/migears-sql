## Verdict / 结论

The previous identifier-injection fix is in place (both INSERT and UPDATE validate identifiers), and it was the highest-value security fix of the round. This round's core problem is **failure-path return values**: the library never checks `prepare()`/`execute()` yet implicitly assumes the caller enabled exception mode.

上一轮的标识符注入已修好（INSERT/UPDATE 都加了校验），这是安全价值最高的一处修复。本轮的核心问题在**失败路径的返回值处理**：库从不检查 `prepare()/execute()` 的返回值，却隐含假设调用方开了异常模式。

## P0

### P0-1

- **Status / 状态**: Open
- **Where / 位置**: `src/SqlSelect.php:118-119,177-178`, `SqlInsert.php:72-74`, `SqlUpdate.php:90-94`, `SqlDelete.php:48-49`
- **Verification / 验证**: reproduced
- **EN**: `prepare()` / `execute()` return values are unchecked and the constructor never sets `ERRMODE_EXCEPTION`. In SILENT mode a database error degrades into `TypeError: bindAllParams(): Argument #1 must be of type PDOStatement, false given` or `Error: Call to a member function bindValue() on false` instead of `SqlException`; and a failed `execute()` is swallowed entirely (a duplicate-key insert returned rowCount=0 with no error)
- **中文**: `prepare()` / `execute()` 返回值不检查，而构造器不设置 `ERRMODE_EXCEPTION`。调用方设为 SILENT 时，数据库错误会退化成 `TypeError: bindAllParams(): Argument #1 must be of type PDOStatement, false given` 或 `Error: Call to a member function bindValue() on false`，而不是 `SqlException`；`execute()` 失败更被完全吞掉（实测重复主键 insert 返回 rowCount=0 且不抛错）

### P2-1

- **Status / 状态**: Open
- **Where / 位置**: `src/SqlDelete.php:32-38`, `src/SqlInsert.php:93-96`
- **Verification / 验证**: reproduced

### P2-2

- **Status / 状态**: Open
- **Where / 位置**: `src/HasWhereClause.php:131,51-58`
- **Verification / 验证**: reproduced (filter)
- **EN**: filter does not support qualified column names: `filter(['u.id' => 1])` throws `SqlException: Invalid filter expression`, while the README's JOIN chapter highlights table aliases and never mentions the limitation; a second `where()` call replaces the conditions but `array_merge`s the parameters, so stale placeholders can remain and break the bind count
- **中文**: filter 不支持限定列名：`filter(['u.id' => 1])` 抛 `SqlException: Invalid filter expression`，而 README 的 JOIN 章节强调多表别名却没说明这个限制；`where()` 二次调用只替换条件而参数仍 `array_merge`，旧占位符可能残留导致绑定数量不匹配
